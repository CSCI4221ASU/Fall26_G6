## 1. Meeting Purpose

The first Sprint 3 meeting focused on translating the CampusConnect product vision into a concrete Project 3 backlog. The team needed to select at least three student-facing features, define a realistic user for each, build a scenario showing the user's interaction with the proposed product, and write one user story per assigned feature. We also clarified ownership, estimates, reviewer assignments, and documentation expectations.

## 2. Agenda and Discussion

### Product vision and student needs

CampusConnect remains a central platform for information about campus events, student organizations, academic resources, and student opportunities. Students should not have to interpret multiple disconnected announcements just to answer simple questions such as “Where can I get tutoring?” or “When is the next campus event?” We agreed that navigation, useful descriptions, and accurate event information were important design considerations.

### Three selected features

1. **Academic Resources — Demetric Noble.** An easy-to-find section for tutoring, advising, and study-support information. The interface should explain what the resources provide and how students access them.
2. **Campus Event Listings — Javian Mack.** An organized view of upcoming activities with event title, date, time, location, and details when available.
3. **Upcoming Event Notifications — Justin Williams.** A reminder concept that helps students recognize upcoming activities and return to the correct event details.

The initial Project 1 product vision also mentions accounts and organization information, but the three features above are the individually assigned Project 3 deliverables. Additional features can be considered in later sprints.

### Personas assigned

Each feature was paired with a distinct illustrative user:

- **Demetric:** Marcus Johnson, a student looking for academic help before a difficult exam.
- **Javian:** Jordan Lee, a new student who wants to discover campus activities.
- **Justin:** Alex Carter, a busy student who benefits from clear event reminders.

These personas are fictional profiles for analysis, not personal information collected from students.

### Scenarios and user-story format

We planned one concrete interaction for each user: finding tutoring, discovering an event, and using a reminder to return to event details. Every story would follow **As a [user], I want [action], so that [benefit]**, with testable acceptance criteria.
